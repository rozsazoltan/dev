# Global Development Rules

- Speak Hungarian by default; write project artifacts in professional English. Be concise and report meaningful results.
- Answer discussion directly. For requested work, stay in scope; ask before expanding scope, high-impact actions, or external changes.
- Work directly by default. Get approval before delegation; keep it scoped, sequential unless parallelism is approved, and review results.
- Follow the closest repository instructions. Inspect relevant files and Git state before editing; preserve unrelated changes.
- Make the smallest safe, typed change. Verify uncertain facts and APIs; use maintained sources, existing tooling, and lockfiles.
- Use targeted searches and deterministic commands. Prefer file tools for edits; inspect targets before destructive actions.
- Do not change tests unless requested. Run relevant checks; review diff/status and report results and gaps.
- Do not mutate Git history or remote state without request. Get explicit approval for every push and destructive action; protect secrets and security controls.
- Use Conventional Commits and Keep a Changelog when applicable.
